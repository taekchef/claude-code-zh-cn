# Claude Code 汉化深度探查与决策

**结论：确实还有多处汉化不到位，而且只继续加翻译词表，无法把当前原生程序完整汉化。** 本次确认了四类问题：旧文案长期漏译、动态拼接没有命中、中文放不进原生槽位、显示文字与程序标识共用。先补用户每天能遇到的授权、按键提示、帮助和设置；共享标识及模型指令不能全局改写。

审计日期：2026-10-09；仓库版本 2.22.0，代码基线 `78e6df7c2e4b54f030fabbd3809a7e831e20d740`。采样时 npm 官方 stable 为 2.1.286，latest 为 2.1.295；版本标签是采样快照，后续可能变化。此报告保留修复前的审计快照；后续实施见[2.23.0 修复与验证记录](localization-fix-2026-10-10.md)和[逐项实施状态](localization-audit-2026-10-09/implementation-decisions.csv)。本轮改动尚未发布。

## 已确认的问题与决定

### 1. 技能授权：优先修，不能只补一个标题

[Issue #260](https://github.com/taekchef/claude-code-zh-cn/issues/260) 报告的是 Mac 原生 2.1.286、插件 2.22.0：基础中文层正常，但技能授权弹窗标题、说明、确认选项和按键提示仍有英文，诊断同时显示缺少补丁标记。

本次官方 2.1.286 二进制 SHA-256 与报告者提供的指纹一致，现有引擎同样命中 **1,344 处**。这支持“补丁已经执行，但覆盖不完整”的判断；缺少标记不能单独证明从未补丁。

| 原文/场景 | 已确认原因 | 决定 |
|---|---|---|
| `Use this skill?` | 可见标题的兜底分支；旧版也已有 | 建议“使用此技能？”；15B 槽能装下 12B 译文 |
| `Use skill "…"?` | 常见分支是动态模板；实际池片段为 `Use skill "`，不是无引号的 `Use skill ` | 标题整体和片段一起审；保留技能名，不误匹配原文 |
| `Claude may use instructions, code, or files from this Skill.` | 直接显示在授权卡片；没有翻译映射 | 补完整说明，保持授权范围的含义 |
| `Yes, and don't ask again for ` | 尾空格是原文的一部分，后面还拼技能名/目录 | 补该显示单元，并验“以后不再询问”完整句 |
| `Yes` / `No` | 同时是按钮文字、确认默认值和问答候选数据；现有英文检查会漏单词 | “是/否”分别能放进 3B/2B 槽，但必须隔离显示引用；不能直接加全局短词映射 |
| `Tab to amend` | 并无对应完整常量；按键组件把 chord、` to `、action 拼起来 | `amend` 在此处确实显示为动作文字；中文句式应在提示组件生成，绑定保持原义 |

原生池会合并同一原文的多个引用。当前引擎主要按整串改池，**尚未证明能对共享池只改某个显示引用**；改变包内调试源码也不会自动改变执行字节码。因此 Yes/No 等项目要先验证定点能力，不能把“方案可描述”当成“现有引擎已能实现”。独占的完整显示常量与共享短词必须分批。

### 2. 动态提示：要查拼接结构，不能按一句英文搜索

按键组件已追到实际输出：它把按键、连接词和动作渲染成显示句。`amend` 在这个调用点是可见说明；其它名为 action 的字段也可能是程序动作标识，要逐处看消费方。

| 类型 | 例子 | 决定 |
|---|---|---|
| 动作提示 | 修改、复制链接、清空历史、切换范围、停止后台 Agent | 统一中文动作措辞，保留真实按键；不能全局改 `cancel`、`open`、`refresh` 等共享短词 |
| 连接词 | ` to `、` in `、` for ` | 改显示句式；不批量替换这些公共词 |
| 带变量的状态行 | 等待任务、审查中、目录、行数、用量及后台会话 | 审模板整体和静态段，保留变量及顺序 |
| 已有片段翻译 | 本次识别出 6 条显示模板的英文静态段已有命中 | 不因“整句没有池常量”重复报漏译；验最终显示 |

### 3. 帮助说明：有真实残留，部分受到原生容量限制

51/50 个帮助入口的原始输出已保存。MCP 添加/查询/列表说明、插件评估长说明、会话导入、后台会话及网关等帮助有真实英文残留。命令名、参数、地址和可复制的命令示例应保留，只翻说明文字。

一个明确例子：添加 MCP 的说明与四组命令示例被合并为 **497B** 的原生窄槽。保留四条命令不变、翻译说明后需要 **796B**；仅四条原样命令转换成 UTF-16 就需要 **602B**。所以这个项目不能靠缩短几个中文词解决。对应最新 Mac 包池偏移为 `14293832`；计算保留所有命令和缩进，译文及测算见[长帮助容量证据](localization-audit-2026-10-09/help-capacity-evidence.json)。

**决定：不删必要命令示例来制造“汉化完成”。** 可放下的完整帮助常量先补；这类长内容要列为原生显示能力的技术验证项目，证明能够真实扩展/隔离显示文本后再交付。也不能修改调试源码副本后宣称原生帮助已变中文。

现有 11 个入口的检查给出稳定版 42、最新版 45 条英文警告；这是按行的启发式警告，包含换行拆分和技术字段误报，不能称作 42/45 个独立漏译。

### 4. 窄槽：把“真漏译”和“应该保留”分开

| 包 | 补丁命中 | 引擎报告槽过窄 | 其中原文与译文相同 |
|---|---:|---:|---:|
| Mac 2.1.285 | 1,345 | 194 | 16 |
| Mac 2.1.286 | 1,344 | 194 | 16 |
| Mac 2.1.295 | 1,342 | 190 | 13 |
| Linux 2.1.295 | 1,336 | 187 | 13 |
| Windows 2.1.295 | 1,336 | 187 | 13 |

这些数量是引擎记录，不能全部解释成界面漏译。窄槽清单中有按键名、命令、品牌等刻意保持原文的身份映射；此外，部分文字是程序哨兵。

| 例子 | 决定 |
|---|---|
| `Enter`、`Claude Code`、`claude doctor` | 保留标准名字；从“翻译失败”统计中排除身份映射 |
| `GitHub App installed!` | 是明确可见的成功标题，21B 槽可评估 20B 的“GitHub应用已装”；还要检查完成回调及相邻说明 |
| `Sign in with your Anthropic account` | 短译“登录 Anthropic 账号”约 30B，可放进 35B 槽；核命令菜单真实消费方 |
| `Hook cancelled` | 是输出比较/取消状态哨兵；保留程序本体，只从明确状态生成显示文案 |
